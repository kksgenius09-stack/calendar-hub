# 온달력 웹 정식 출시 설계

## 목표

온달력을 `ondalcalendar.kr`에서 개인 운영자가 제공하는 공개 웹 서비스로 정식 출시한다. Google OAuth 테스트 사용자 방식에 의존하지 않고, 사용자가 서비스의 데이터 처리 방식과 삭제 절차를 확인할 수 있으며, Google Calendar 민감 권한 검증을 신청할 수 있는 상태를 만든다.

## 운영 정보

- 서비스명: 온달력
- 운영 주체 표기: 온달력 운영자
- 고객지원 및 개인정보 문의: `kksgenius2@gmail.com`
- 출시 형태: 개인 운영 웹 서비스
- 공개 주소: `https://ondalcalendar.kr`

## 현재 데이터 처리 구조

온달력은 별도 이메일·비밀번호 회원가입을 제공하지 않는다. 사용자가 Google로 시작하면 Supabase Auth에 사용자 식별 레코드가 생성된다.

서버에 저장되는 정보는 다음과 같다.

- Google 사용자 식별값, 이메일 주소와 Google이 로그인 과정에서 제공하는 기본 프로필 정보
- Google OAuth 토큰
- iCloud 계정 이메일과 앱 전용 암호
- 회사 CalDAV 서버 주소, 계정 ID 또는 이메일, 비밀번호 또는 앱 암호
- 캘린더 연결 계정 표시 이름
- 음력 반복 일정의 제목, 음력 월·일, 대상 캘린더, 생성된 외부 일정 식별값과 날짜

Google OAuth 토큰과 iCloud·CalDAV 인증정보는 서버 저장 전에 AES-GCM 방식으로 암호화한다. 일반 캘린더 일정은 연결된 외부 캘린더에서 필요한 기간만 실시간으로 조회하며, 온달력 데이터베이스에 복제 보관하지 않는다. 음력 반복 일정은 향후 발생분 관리에 필요한 최소 정보만 별도로 저장한다. 달력 표시, 자동 동기화 간격, 기본 저장 캘린더 등 기기별 설정은 브라우저 로컬 저장소에 저장한다.

## 공개 페이지

### 개인정보처리방침

`/privacy`에 다음 내용을 공개한다.

- 처리하는 개인정보 항목과 수집 방법
- 개인정보 이용 목적
- 처리 및 보유 기간
- 외부 서비스 및 국외 처리 가능성
- Supabase와 Cloudflare 등 서비스 제공에 필요한 처리업체
- Google, Apple, 회사 그룹웨어로부터 데이터를 조회하고 변경하는 방식
- 암호화와 접근 통제 등 안전성 확보 조치
- 이용자의 열람·정정·삭제·처리정지 요청 방법
- 개인정보 보호 담당자와 문의 이메일
- 시행일과 변경 고지 방식

보유 기간은 서비스 이용 및 연결 유지 기간으로 하며, 사용자의 삭제 요청과 본인 확인이 완료되면 법령상 별도 보존 의무가 없는 계정·연결정보·음력 반복정보를 7일 이내 삭제한다.

### 이용약관

`/terms`에 다음 내용을 공개한다.

- 서비스 기능과 적용 범위
- Google·Apple·회사 그룹웨어 등 외부 서비스 의존성
- 이용자의 계정 및 앱 전용 암호 관리 책임
- 금지 행위
- 서비스 변경·중단 가능성
- 일정 데이터 손실에 대한 백업 권고와 책임 범위
- 지식재산권
- 계약 종료와 데이터 삭제
- 준거법과 분쟁 처리

### 고객지원 및 데이터 삭제 안내

`/support`에 다음 내용을 공개한다.

- 문의 이메일
- 캘린더 연결 해제 방법
- 계정 및 서버 저장정보 삭제 요청 방법
- 삭제 요청 시 본인 확인에 필요한 최소 절차
- 본인 확인 완료 후 7일 이내 처리한다는 안내
- 삭제 대상: Supabase 사용자 레코드, 저장된 연결정보, 음력 반복정보
- 외부 캘린더에 이미 생성된 일정은 사용자의 Google·iCloud·회사 캘린더에 남을 수 있으며 사용자가 해당 외부 서비스에서 별도로 삭제해야 한다는 안내

초기 출시에서는 자동 회원탈퇴 기능을 만들지 않는다. 사용자는 지원 이메일로 삭제를 요청하며 운영자가 본인 확인 후 처리한다.

## 화면 연결

- 랜딩 화면 하단에 개인정보처리방침, 이용약관, 고객지원 링크를 항상 노출한다.
- 캘린더 화면의 설정 또는 하단 영역에서도 같은 링크에 접근할 수 있게 한다.
- 새 공개 페이지는 기존 온달력의 차분한 시각 체계를 유지하고 모바일·데스크톱에서 읽기 편한 단일 열 문서 형태로 제공한다.
- 각 문서에는 서비스명, 최종 수정일, 고객지원 이메일을 명확히 표시한다.

## Google OAuth 프로덕션 준비

1. Google Auth Platform의 브랜딩 정보를 `온달력`과 `ondalcalendar.kr` 기준으로 통일한다.
2. 홈페이지, 개인정보처리방침, 이용약관 URL을 Google Cloud에 등록한다.
3. Search Console에서 `ondalcalendar.kr` 소유권을 확인한다.
4. Data Access에 실제 사용하는 Calendar 읽기·쓰기 범위만 선언한다.
5. 앱을 Testing에서 In production으로 전환한다.
6. 민감한 Calendar 범위에 대해 검증을 신청한다.
7. 로그인, 동의, 일정 조회, 일정 생성·수정·삭제가 보이는 미등록 YouTube 시연 영상을 제출한다.
8. 각 권한이 온달력 핵심 기능에 필요한 이유를 구체적으로 설명한다.

검증 승인 전에는 프로덕션 상태에서도 미확인 앱 경고가 표시될 수 있다. 정식 출시 완료 기준은 검증 승인 후 일반 Google 사용자가 테스트 사용자 등록이나 경고 우회 없이 로그인할 수 있는 상태다.

## 배포와 검증

- 공개 페이지를 구현한 뒤 기존 앱 빌드가 성공해야 한다.
- 개인정보처리방침·이용약관·지원 페이지가 직접 URL과 화면 링크 양쪽에서 열려야 한다.
- 모바일과 데스크톱에서 문서가 잘리지 않고 읽혀야 한다.
- `ondalcalendar.kr`에서 Google 로그인 후 `/auth/callback`으로 정상 복귀해야 한다.
- 캘린더 연결정보가 사용자별로 분리되고 연결 해제 시 해당 공급자의 저장 인증정보가 삭제되는 기존 동작을 회귀 테스트한다.
- 배포 후 공개 URL에서 HTTPS와 주요 페이지의 HTTP 200 응답을 확인한다.

## 제외 범위

- 자동 회원탈퇴 및 자동 데이터 삭제 UI
- 유료 결제와 구독
- 광고 삽입
- 모바일 앱 심사 및 출시

이 항목들은 웹 정식 출시와 Google OAuth 검증 이후 별도 작업으로 진행한다.
