# 온달력 데스크톱 일정 조작 및 연결 오류 안내 설계

## 목적

Windows 웹 사용자가 월간 달력에서 기존 일정을 빠르게 이동하거나 기간을 조정할 수 있게 한다. iCloud와 회사 CalDAV 연결이 실패했을 때에는 원인과 해결 방법을 이해할 수 있게 한다. Google OAuth 권한, 로그인 흐름, 앱 이름과 심사 설정은 변경하지 않는다.

## 범위

### 포함

- 일반 일정을 다른 날짜로 드래그하여 이동
- 월간 일정 막대의 왼쪽·오른쪽 끝을 드래그하여 시작일·종료일 변경
- 드래그 중 변경될 날짜 범위 미리보기
- iCloud 및 회사 CalDAV 연결 오류의 분류와 해결 안내
- 연결 오류 재시도, 상세 정보 표시와 기술 코드 복사
- 날짜 계산, 조작 허용 여부와 오류 매핑에 대한 자동 테스트

### 제외

- 반복 일정의 드래그 이동 또는 기간 변경
- 읽기 전용 회사 일정의 변경
- 일정 복제, 빠른 날짜·시간 버튼, 최근 사용 캘린더 자동 선택
- Google OAuth 권한·동의 화면·리디렉션 주소 변경
- 달력 UI 라이브러리 도입 또는 현재 달력 전체 교체
- 모바일 전용 조작 최적화

## 접근 방식

현재 월간 달력과 이벤트 API 위에 브라우저 Pointer Events 기반 조작을 추가한다. 외부 드래그 라이브러리를 도입하지 않는다. 날짜 계산과 조작 가능 여부는 UI에서 분리한 순수 함수로 만들고, `page.tsx`는 포인터 상태와 저장 요청만 조정한다.

이 방식은 현재 디자인, 음력 표시, 다중 캘린더 및 기간 막대 배치를 유지하면서 필요한 기능만 추가한다. 일정 변경은 기존 공급자별 `PATCH` 경로를 사용하므로 새로운 Google 권한이 필요하지 않다.

## 일정 이동 및 기간 변경

### 조작 가능 여부

다음 조건을 모두 만족하는 일정만 조작할 수 있다.

- 반복 규칙 또는 온달력 음력 반복 시리즈에 속하지 않는다.
- 회사 일정인 경우 개인 쓰기 가능 캘린더에 속한다.
- 시작일과 공급자 일정 식별정보가 유효하다.

반복 일정과 읽기 전용 일정에는 이동 커서와 기간 조절 손잡이를 표시하지 않는다. 마우스를 올리거나 조작을 시도하면 각각 `반복 일정은 편집창에서 변경해 주세요.` 또는 `읽기 전용 일정은 이동할 수 없어요.`를 안내한다.

### 본문 드래그 이동

- 포인터가 일정 본문에서 시작되고 최소 이동 거리를 넘으면 드래그로 판정한다.
- 원래 일정의 날짜 기간 길이를 그대로 유지한다.
- 포인터가 놓인 날짜를 새 시작일로 삼고 같은 기간 길이만큼 종료일을 이동한다.
- 시간이 있는 일정은 시작·종료 시각을 유지하고 날짜만 이동한다.
- 클릭으로 끝난 경우에는 기존처럼 일정 편집창을 연다.

### 기간 조절

- 월간 일정 막대가 실제 일정의 시작을 포함하는 구간에는 왼쪽 손잡이를 표시한다.
- 실제 일정의 종료를 포함하는 구간에는 오른쪽 손잡이를 표시한다.
- 왼쪽 손잡이는 시작일만, 오른쪽 손잡이는 종료일만 변경한다.
- 시작일은 종료일 뒤로, 종료일은 시작일 앞으로 넘어갈 수 없다.
- 단일 날짜 일정의 오른쪽 손잡이를 끌면 여러 날짜 일정으로 확장할 수 있다.
- 주 또는 월 경계를 넘어가도 실제 날짜를 기준으로 계산한다.

### 미리보기 및 저장

- 드래그 중 새 날짜 범위를 반투명 막대로 표시한다.
- 포인터를 놓기 전에는 서버와 실제 일정 상태를 변경하지 않는다.
- 유효한 날짜에 놓으면 해당 공급자의 기존 `PATCH` API로 저장한다.
- 저장 중에는 같은 일정을 다시 조작하지 못하게 하고 `변경 중…` 상태를 표시한다.
- 성공 시 일정을 다시 불러오고 이동은 `일정을 이동했어요.`, 기간 조절은 `기간을 변경했어요.`라고 안내한다.
- 실패 시 낙관적 위치를 확정하지 않고 기존 일정 표시를 유지한 채 오류를 안내한다.

## 연결 오류 안내

### 공통 오류 모델

iCloud와 회사 CalDAV 연결 API는 사용자 비밀값을 포함하지 않는 안정적인 오류 코드를 반환한다.

| 오류 코드 | 사용자 안내 | 해결 방법 |
| --- | --- | --- |
| `AUTH_REQUIRED` | 온달력 로그인이 만료됐어요. | Google 계정으로 다시 로그인 |
| `INVALID_CREDENTIALS` | 계정 정보를 확인할 수 없어요. | 계정과 앱 전용 암호 또는 비밀번호 확인 |
| `PERMISSION_DENIED` | 캘린더 사용 권한이 없어요. | 회사 관리자에게 CalDAV 권한 요청 |
| `INVALID_SERVER_URL` | 서버 주소가 올바르지 않아요. | `https://`를 포함한 CalDAV 주소 확인 |
| `SERVER_UNREACHABLE` | 캘린더 서버에 연결할 수 없어요. | 네트워크와 서버 상태 확인 후 재시도 |
| `CALDAV_PATH_NOT_FOUND` | CalDAV 캘린더 경로를 찾지 못했어요. | 회사에서 제공한 정확한 CalDAV 주소 확인 |
| `NO_CALENDARS` | 사용할 수 있는 캘린더가 없어요. | 공급자 계정에 캘린더가 생성되어 있는지 확인 |
| `TEMPORARY_ERROR` | 일시적인 연결 오류가 발생했어요. | 잠시 후 다시 시도 |

기존 공급자별 내부 오류는 서버에서 위 공통 코드로 변환한다. HTTP 상태와 CalDAV 응답은 진단에 활용하지만 비밀번호, 앱 전용 암호, OAuth 토큰, 암호화된 연결정보는 응답이나 상세 정보에 포함하지 않는다.

### 화면 구성

연결 모달 안에서 오류가 발생한 위치에 다음을 표시한다.

- 오류 제목과 짧은 설명
- 사용자가 수행할 해결 방법
- 입력값을 유지한 상태의 `다시 시도` 버튼
- 접을 수 있는 `상세 정보`
- 민감정보가 없는 공급자·공통 오류 코드·발생 단계의 `복사` 버튼

입력 누락은 필드 가까이에서 바로 안내하고 서버 요청을 보내지 않는다. 연결 성공 시 기존 연결 완료 흐름을 유지한다.

## 구성 요소 경계

- 날짜 조작 유틸: 이동·시작일 변경·종료일 변경과 금지 조건을 입력받아 새 범위를 반환한다.
- 월간 일정 표현: 드래그 대상, 양 끝 손잡이와 미리보기를 렌더링한다.
- 페이지 조정 계층: 포인터 생명주기, 드래그 상태, 저장 요청과 알림을 관리한다.
- 연결 오류 매퍼: 공급자 내부 오류를 공통 오류 모델로 변환한다.
- 연결 모달 오류 패널: 공통 오류 모델을 사용자 문구와 재시도 동작으로 표현한다.

각 단위는 공급자 네트워크 호출과 분리해 순수 데이터로 테스트할 수 있게 한다.

## 테스트 전략

테스트 우선 방식으로 다음 동작을 검증한다.

- 일반 일정 이동 시 기간 길이와 시간이 유지된다.
- 왼쪽·오른쪽 기간 조절이 올바른 경계를 변경한다.
- 시작일과 종료일이 역전되지 않는다.
- 단일 일정이 여러 날짜 일정으로 확장된다.
- 주·월 경계를 넘는 이동과 조절이 정확하다.
- 반복 일정과 읽기 전용 회사 일정은 조작 불가다.
- 클릭과 드래그가 최소 이동 거리로 구분된다.
- 공급자 오류가 올바른 공통 코드와 해결 안내로 매핑된다.
- 상세 정보에 비밀번호·앱 전용 암호·토큰이 포함되지 않는다.
- 기존 전체 테스트, 빌드와 린트가 통과한다.

## 배포 및 확인

기존 API와 화면을 확장하므로 데이터 마이그레이션은 필요하지 않다. 전체 자동 테스트와 린트가 통과한 뒤 운영 사이트에 배포한다. 배포 후 일반 일정 이동, 기간 확장, 금지 일정의 비활성 상태와 iCloud·회사 연결 오류 안내를 데스크톱 브라우저에서 확인한다.
